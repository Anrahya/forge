You own the shape. The build context owns the code.

1. GROUND the affected subsystem. Two cited examples for every pattern about to be written.
2. SCOUT: what exists outside the repo. A library that already does this beats code. An approach others abandoned is a warning.
3. SHAPE: name the data shape and its organizing structure first (`model-the-domain`). Two structurally distinct candidates. Pick on interface depth. Settle any empirical fork with a prototype, never a debate.
4. BUILD in verifiable units. Each unit: hypothesis, check first when cheap, smallest change, run, log a decision row, commit.
5. VERIFY on the real surface through the project verify skill when `surface` is not `none`.
6. REVIEW. Blocking findings go back to BUILD with `review.md`.
7. REPORT. Tables for design alternatives.
